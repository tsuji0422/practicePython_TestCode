# GitHub Actionsの基本

一応基本的な内容と応用的な内容がある

## ファイルの場所:

GitHub Actionsのワークフローは、`.github/workflows` ディレクトリ内にYAMLファイルで定義します。このディレクトリはリポジトリのルートに配置する必要があります。

- .github/workflows/: このディレクトリ内に、ワークフローを定義するYAMLファイルを配置します。
- *.yml or *.yaml: ワークフローファイルの拡張子は .yml または .yaml です。

例えば、main.ymlというワークフローファイルを定義する場合、ファイルパスは次のようになります。

    .github/workflows/main.yml

## トリガー (実行のきっかけ):

ワークフローは、特定のイベントをトリガーとして実行されます。様々なイベントをトリガーとして設定できますが、代表的なものをいくつか紹介します。

- push:                 
  - リポジトリにコードをプッシュした時。特定のブランチへのプッシュに限定することも可能です。
- pull_request:         
  - プルリクエストが作成、更新、またはクローズされた時。
- schedule:             
  - 定期的に実行。cron構文で実行スケジュールを指定できます。
- workflow_dispatch:    
  - 手動でワークフローを実行。GitHubのUIから実行できます。
- release:              
  - リリースが作成された時。
- issue_comment:        
  - イシューにコメントが追加された時。特定のキーワードを含むコメントに限定することも可能です。

例: pushイベントをトリガーとしたワークフロー:

    on:
    push:
        branches:
        - main  # mainブランチへのプッシュ時にワークフローを実行


例: scheduleイベントをトリガーとしたワークフロー:

    on:
    schedule:
        - cron: '0 0 * * *'  # 毎日午前0時にワークフローを実行


## ジョブ (Jobs):

* ワークフロー内で実行される一連のタスクをグループ化したものです。
* 複数のジョブを定義でき、並列または順次実行させることができます。
* 各ジョブは指定された仮想環境 (runner) 上で実行されます。

## ステップ (Steps):

* 各ジョブ内で実行される個々のコマンドやアクションです。
* アクションとは、GitHubやコミュニティによって提供されている再利用可能なコードの単位です。
* ステップは順番に実行され、前のステップが成功した場合のみ次のステップが実行されます。

**例：**

```yaml
on: push

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3  # リポジトリをチェックアウトするアクション
      - run: npm install  # 依存関係をインストールするコマンド
      - run: npm test  # テストを実行するコマンド
```

上記の例では、`build` というジョブが定義されており、`ubuntu-latest` 環境で実行されます。ジョブ内には3つのステップがあり、それぞれ `actions/checkout@v3` アクションの実行、`npm install` コマンドの実行、`npm test` コマンドの実行を行います。

**なぜジョブとステップが重要なのか？**

* **複雑なワークフローの構築:** 複数のジョブとステップを組み合わせることで、複雑なワークフローを定義できます。
* **再利用性の向上:** アクションを利用することで、共通のタスクを再利用し、ワークフローの記述を簡潔にできます。
* **柔軟な実行制御:** ジョブの依存関係や条件を設定することで、ワークフローの実行を柔軟に制御できます。

**まとめ:**

GitHub Actionsの基本を理解するには、**ファイルの場所、トリガー、ジョブ、ステップ** の4つの要素を把握することが重要です。 これらの要素を理解することで、GitHub Actionsを効果的に活用し、開発ワークフローを自動化することができます。

**他に基本的なこととしては、ワークフローの実行環境 (runner) や、シークレット (secrets) の設定などがありますが、これらは少し応用的な内容になります。** まずは上記の4つの要素をしっかりと理解することが重要です。

というわけで続きに応用的な内容を記述する

## 実行環境 (Runner):

* **役割:** ワークフローのジョブを実行する仮想マシンまたはコンテナを提供します。
* **種類:** GitHubホストランナーとセルフホストランナーの2種類があります。
    * **GitHubホストランナー:** GitHubが提供する仮想環境で、様々なOS (Ubuntu, Windows, macOS) とソフトウェアがプリインストールされています。手軽に利用できます。
    * **セルフホストランナー:** 自分で用意した環境 (物理マシン、仮想マシン、コンテナなど) でジョブを実行できます。特定のソフトウェアや設定が必要な場合に便利です。
* **指定方法:** ジョブ定義の中で `runs-on` キーワードを使って指定します。
    ```yaml
    jobs:
      my_job:
        runs-on: ubuntu-latest  # GitHubホストランナーのUbuntu最新版を指定
    ```
* **重要性:** 実行環境によって利用可能なソフトウェアやリソースが異なるため、適切な環境を選択することが重要です。

## アクション (Actions):

* **役割:** ワークフロー内で実行するタスクをカプセル化した再利用可能なコードユニットです。
* **メリット:** 
    * 複雑なタスクを簡単に実行できます。
    * ワークフローの記述を簡潔にし、可読性を向上させます。
    * コミュニティで作成されたアクションを再利用することで、開発時間を短縮できます。
* **利用方法:** `uses` キーワードを使ってアクションを指定します。
    ```yaml
    steps:
      - uses: actions/checkout@v3  # リポジトリをチェックアウトするアクション
    ```
* **公開場所:** GitHub Marketplace ([https://github.com/marketplace?type=actions](https://github.com/marketplace?type=actions)) で様々なアクションが公開されています。
* **重要性:** アクションを活用することで、効率的にワークフローを構築し、メンテナンス性を向上させることができます。

## シークレット (Secrets):

* **役割:** APIキー、パスワード、トークンなどの機密情報を安全に保存し、ワークフロー内で利用できるようにします。
* **メリット:**
    * 機密情報をリポジトリに直接コミットする必要がなく、セキュリティを向上させます。
    * ワークフロー内で機密情報を使用する際に、平文で記述する必要がありません。
* **設定方法:** リポジトリの設定画面からシークレットを登録できます。
* **利用方法:** `secrets.<シークレット名>` の形式でワークフロー内で参照できます。
    ```yaml
    steps:
      - run: echo ${{ secrets.MY_API_KEY }}
    ```
* **重要性:** 機密情報を安全に管理し、ワークフローのセキュリティを確保するために不可欠です。

**まとめ:**

実行環境、アクション、シークレットは、GitHub Actionsを効果的に活用するための重要な要素です。 これらの要素を理解し、適切に設定することで、安全で効率的なワークフローを構築することができます。

より詳細な情報については、公式ドキュメントを参照することをお勧めします。 特に、セキュリティに関する情報は重要ですので、必ず確認してください。





# YAMLファイルの文法

## GitHub Actions YAMLファイルの基本的な記述方法と文法

GitHub Actionsのワークフローは、YAML (YAML Ain't Markup Language) 形式で記述します。YAMLは人間が読みやすく、データシリアライズにも適したフォーマットです。ここでは、GitHub Actions YAMLファイルの基本的な記述方法と文法について解説します。

**基本的な構成要素:**

* **`name` (任意):** ワークフローの名前。省略した場合は、ファイルパスが名前として使用されます。
* **`on` (必須):** ワークフローをトリガーするイベントを指定します。
* **`jobs` (必須):** 実行するジョブを定義します。

**YAMLの文法:**

* **インデント:** インデントはスペース2つを使用します。タブは使用できません。インデントによって階層構造を表現します。
* **キーと値:** `キー: 値` の形式で記述します。キーと値の間にはスペースが必要です。
* **リスト:** `- 項目1` のように、ハイフンとスペースを使ってリストを表現します。
* **文字列:** クォーテーションで囲む必要はありませんが、特殊文字を含む場合はクォーテーションで囲みます。

**例：**

```yaml
name: My Workflow

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - run: echo "Hello, world!"
```

**解説:**

* `name: My Workflow`: ワークフローの名前を `My Workflow` としています。
* `on: push: branches: - main`: `main` ブランチへのプッシュをトリガーとして設定しています。
* `jobs: build`: `build` という名前のジョブを定義しています。
* `runs-on: ubuntu-latest`: ジョブを実行する環境として `ubuntu-latest` を指定しています。
* `steps`: ジョブ内で実行するステップを定義しています。
* `uses: actions/checkout@v3`: `actions/checkout@v3` アクションを使用してリポジトリをチェックアウトします。
* `run: echo "Hello, world!"`: `echo "Hello, world!"` コマンドを実行します。
